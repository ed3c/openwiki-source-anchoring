# Multi-OpenWiki Study Review Checklist

Before scoring:

- [ ] Exact source repository and 40-character commit recorded
- [ ] Every output has a unique ID, run ID, method, and provenance status
- [ ] Source snapshot and generated-output roots are isolated
- [ ] Candidate output roots do not overlap
- [ ] Development, public, and holdout paths are distinct and spent state is recorded
- [ ] Primary reader-facing outcomes were frozen before candidate scoring
- [ ] Task author, answerer, judge, and executor read boundaries are enforced outside prompts
- [ ] Raw prompts, answers, mappings, verdicts, test receipts, latency, tokens, and costs are preserved
- [ ] Lexical validity and semantic support are reported separately
- [ ] Repository × generation run is the top-level experimental unit
- [ ] Repeated paired runs and human calibration support model-judge claims
- [ ] Conclusions are labeled observed, supported inference, hypothesis, or not licensed
- [ ] Optional tool licenses, versions, telemetry, provider dependencies, and removal paths are recorded
