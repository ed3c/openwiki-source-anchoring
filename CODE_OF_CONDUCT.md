# Code of Conduct

## Our standard

Project participants are expected to:

- discuss evidence, implementations, and experiments rather than attacking people;
- distinguish observed facts from inference and opinion;
- give specific, actionable feedback;
- acknowledge uncertainty and correct mistakes publicly;
- respect different experience levels, languages, identities, and backgrounds;
- avoid harassment, threats, discriminatory language, sexualized attention, and deliberate disruption.

Strong disagreement is welcome. Personal abuse is not.

## Scope

This code applies in repository issues, pull requests, reviews, discussions, release notes, and other public spaces where someone represents this project.

## Research and review conduct

Because this repository evaluates generated work, reviewers must not:

- manipulate fixtures or omit failed runs without disclosure;
- present agent output as independently verified evidence;
- expose private target code, prompts, credentials, or personal data;
- pressure contributors to reveal private model conversations or proprietary artifacts;
- use review roles as a pretext for humiliation.

Report methodological mistakes plainly and preserve the evidence needed to correct them.

## Enforcement

The maintainer may edit or remove comments, close or lock discussions, reject contributions, or restrict participation when behavior violates this policy.

When possible, enforcement will state:

- the behavior that violated the standard;
- the action taken;
- what would be required for participation to resume.

## Reporting

For conduct concerns, contact the maintainer privately through the GitHub profile. Do not include security vulnerabilities or sensitive personal data in a public conduct report.

Good-faith reports and participants in an incident must not be retaliated against.
